# Tidy + landing rerun — working notes (card `t_fa64f594`, session 2)

## Why the parent run landed `moved=0`

The server's own debug line settles it:

```
[debug][Flow] trip deposit claim=-1327346010:15577 moved=0 target=piece_chest_wood(Clone)
               at=(2.8,-0.5) why=no rule remaining=0
```

`remaining=0` means the two tickets were **removed**, not requeued. For an Empty Pockets trip the
tickets are `FlowSource.Ground` and `FlowTicket.IsValid()` answers `Drop != null`
(`src/Flow/FlowTicket.cs:65`), so `Land()` removed both because their drops were **gone**
(`src/Flow/Trip.cs:289`). The drops are spawned at the nisse's own feet
(`OrderService.MaterialisePockets`: `origin = nisse.transform.position`, +0.55 m ring).

Client log, same scene:

```
gc state player=Stranger id=-202584743 pos=0.88,34.35,1.44
gc state nisse ... pos=-0.99,34.35,2.00
```

Bowl at `(-1.60, 1.00)`; the player settled at `(0.88, 1.44)`, 2.52 m from the bowl and **1.95 m from
the nisse** — inside Valheim's auto-pickup radius. The player re-absorbed its own handover
(`hud top='Added Coal x12'` was seen in the earlier scene), which destroyed the drops the trip was
carrying. Nothing in the trip's landing check is wrong: it landed what was left, which was nothing.

So the fix is scene geometry, not code: **the bowl must be ≥ ~4.5 m from the player**, because the
handover drop zone is the nisse's home point (`bowl + forward * 1.5 m`). At 4.6 m the worst-case drop
is 3.1 m from the player.

## Geometry rules now encoded in `make-scene-at.py`

| Rule | Why |
|---|---|
| build at the position the client reports at `gc ready`, never move the player | a transform set / `TeleportTo` fights the server's copy of the position and snaps back mid-order |
| bowl at `player + (-4.60, -0.40)` (4.6 m) | keeps the handover drop zone out of auto-pickup range |
| chest A at `player + (1.50, 1.70)` (2.3 m) | `alt <prefab>` on the client addresses the **nearest** container, so the Tidy source must be the nearest one |
| chest B at `player + (-0.90, 3.20)` — **smaller x than chest A** | `husnisse_rule net piece_chest_wood on <i>`, `fill`, `container` and `zdo` all index containers sorted by x then z, so chest B is index 0 (the one put on the network) and chest A index 1 (the coal) |
| a 4×3 `wood_floor` grid at the player's own y, pieces 0.10 above it | the dedicated server has no terrain colliders: a character with nothing under it falls through the world, and a floating deck decays |
