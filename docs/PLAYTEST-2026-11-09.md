## Root cause of B5/B6 — the server never saw the bowl

Server `BepInEx/BSBLogs/Husnisse.log` contains only `world ready` with `claims=0` and no claim
registration. The client log contains `claim registered` with the same session. Server log shows 63
location placements between 02:46 and 02:50 and no zone load for the player's area.

This matches the earlier spike finding: on this rig the dedicated server does not load player zones, so
player-built bowls exist only on the client. Consequences:

- Rounds are server-only, so no ground collection (B6).
- The client's nisse is a client-created ZDO; nothing authoritative survives a relog **if the server never
  owned it**, and the test could not separate that from the nisse having died earlier (B5 is unproven).
- Empty Pockets and feeding ran **client-side**, which is exactly the H1 risk in `CODE-REVIEW.md`. They
  appeared to work, but the server did not arbitrate them.

Until the rig loads zones (or testing moves to a client-hosted world), server-side behaviour cannot be
judged from this setup.
